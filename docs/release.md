# Release Notes Workflow

Use `CHANGELOG.md` as the release notes source of truth.

## Before a release

1. Move entries from `Unreleased` into a versioned section, for example `## 3.1.0 - 2026-05-10`.
2. Run verification:
   - `pnpm format:check`
   - `pnpm test`
   - `pnpm build`
   - `pnpm build:example`
3. Confirm `dist/index.d.ts` is generated by `pnpm build`.
4. Publish with the existing release process.

## Changelog categories

- `Added` for new components, options, events, and docs.
- `Changed` for behavior changes that preserve compatibility.
- `Fixed` for bug fixes.
- `Removed` only for breaking removals.
